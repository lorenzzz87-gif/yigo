> 本文件是本仓库的唯一需求来源。开始任何任务前先读完本文件；与本文件冲突的做法一律以本文件为准。需求变更由产品负责人（Lorenzo）确认后改这里。

## 0. 一句话

「半山」是一个打开浏览器就能进的 3D 中式山寺：不说话、不比较，和陌生人同坐一殿，歇一会儿再走。对标韩国 Sansa（sansatemple.com），差异在于中式水墨审美、时间感（晨钟暮鼓、二十四节气）、「一炷香」静坐和「一盏灯」。

- 品牌名：**半山**；副标题：**云上禅寺**。品牌名里不出现「寺」。
- 目标用户：海外华语用户（华人、港台），20–35 岁，压力大的年轻人；不以佛教信众为核心。
- 市场：v1 只做海外。**不在中国大陆备案、不在大陆平台投放**。大陆用户能访问就访问，不做专门适配。
- 界面语言：v1 只做简体中文；文案全部放在 `packages/shared/src/copy/zh-CN.ts`，为 v1.1 繁体和英文留好结构。

## 1. 产品原则（写代码时的判断标准）

1. **零门槛**：不注册、不下载，打开网址 10 秒内进殿。
2. **同在，不交流**：能看到别人，但没有聊天、私信、评论、点赞、关注。
3. **没有数字压力**：不显示功德值、排行榜、签到、连续天数、礼拜次数。
4. **不承诺灵验**：不卖开光、不卖功德，不用任何真实寺院的名字或形象。
5. **少即是多**：每加一个功能，先问它会不会让人更难安静。答不上来就不加。

**明确不做（v1 及以后都不做，除非本文件修改）**：聊天和社交关系、付费道具和皮肤、公开展示的许愿墙、AI 算命和解签、广告、账号系统、推送轰炸。

## 2. 功能范围

### 2.1 v1 必做

| # | 模块 | 规格 |
|---|---|---|
| 1 | 进殿 | 山门加载页：一张静态插画加进度条，文案「山门已开，稍候。」。自动分配小沙弥角色和随机名字（见 §8），可点一次「换个名字」。按时区分配殿，每殿 100 人，满员自动开新殿。 |
| 2 | 移动与镜头 | 第三人称跟随。点击地面移动（寻路用简单导航网格或预设可走区域）；拖动旋转视角；双指或滚轮缩放。镜头有俯仰限位，不能穿墙。 |
| 3 | 身体动作 | 底部栏只有四个按钮：合十、礼拜、木鱼、念珠。其他人能看到。礼拜只能在坐到蒲团上时使用，其余随时可用。 |
| 4 | 物件交互 | 走近物件（2 米内）才浮出按钮：蒲团「坐下」、香炉「上一炷香」、功德箱「随喜」。离开就消失。 |
| 5 | 一炷香 | 在香炉上香后，自己视角里出现一炷香，约 5 分钟燃尽（香身缩短、烟变细）；燃尽时响一声磬，轻轻提示「一炷香尽了」。别人能看到香炉里多了一炷香。**不计数、不累计**。 |
| 6 | 听 | 诵经（《心经》一版）、自然声（雨、林、风铃）。**默认静音**，一键开启。开发阶段用占位音频。 |
| 7 | 晨钟暮鼓 | 按用户当地时间，07:00 敲钟、18:30 击鼓，全殿同时听到（同殿的人在同一时区，见 §4.3）。前 5 分钟在角落显示「钟声将至」。可选：用户授权后发浏览器通知，只在钟鼓前提醒，每天最多两次。 |
| 8 | 昼夜 | 场景光照跟随当地时间：晨（05–09）、日（09–17）、暮（17–20）、夜（20–05），切换时平滑过渡 60 秒。白天用水墨配色，暮和夜用暖灯配色（§3）。 |
| 9 | 节气 | 按日期判断当前节气（建议用 `lunar-javascript` 计算）。v1 做「四季 × 天气（晴、雨、雪、雾）」组合，每个节气映射到一种组合；节气当天，山门加载页显示节气名和一句话（文案见 §8）。 |
| 10 | 一盏灯 | 写一句话（≤ 30 字）点一盏灯，亮 24 小时。**文字只存在用户自己的浏览器里（localStorage），永远不发给服务器**；服务器只收到「点了一盏」的信号，只存计数。殿内出现一盏无名灯光，所有人可见。每个匿名 ID 每天 1 盏。自己可以在「我的灯」里看到自己的话。 |
| 11 | 随喜 | 功德箱物件，走近才能点；打开一个说明面板（钱的去向）和外链按钮（Stripe Payment Link，金额用户自选）。不弹窗、不提醒、不换取任何东西。链接地址放在环境变量里，未配置时隐藏功德箱的随喜按钮。 |
| 12 | 告别 | 关闭页面或点「下山」时，显示一句告别语和下次钟声时间，例如「下次钟声：明早 7:00」。 |
| 13 | 降级 | WebGL 不可用或设备太弱（首帧 > 8 秒或 FPS 持续 < 15）时，显示 2D 静态大殿插画加声音，保留一炷香、一盏灯和钟鼓，**不能白屏**。 |
| 14 | 统计 | 用无 cookie 的统计（Plausible 或自建事件接口），只记匿名事件，见 §6。 |

## 3. 美术与视觉规范

**方向**：白天「水墨留白」，傍晚起切到「绢本暖暮」的灯火。参考画布「半山 · 美术方向提案」的方向 A 和 C。

**场景**：一座半山腰的小寺，路线是 山门 → 石阶 → 庭院 → 大殿。大殿内 100 个蒲团（10 × 10），一尊佛像，一只香炉，一只功德箱。远处是层叠的山和流动的雾。

**风格**：低多边形（low-poly）加手绘贴图，不走写实。佛像同样低多边形，用石或木的本色，**不用写实金身**。场景和佛像都要原创造型，**不得仿任何真实寺院**，也不得仿 Sansa。

**白天色板（水墨留白）**

| 名称 | 色值 | 用途 |
|---|---|---|
| 宣纸 | #EDE8DD | 天空、雾、地面亮部 |
| 焦墨 | #2B2B28 | 屋顶、山崖、轮廓 |
| 淡墨 | #8A8578 | 远山、僧衣 |
| 雾灰 | #C9C3B5 | 中景、雾带 |
| 朱砂 | #B5432E | 只用于灯笼和印章 |

**暮夜色板（绢本暖暮）**

| 名称 | 色值 | 用途 |
|---|---|---|
| 旧绢 | #E6D5B5 | 暮色天空 |
| 赭石 | #A8653A | 木构、袈裟 |
| 淡墨 | #5B5348 | 近景山体 |
| 灯火 | #E3A14B | 灯、窗、一盏灯 |
| 暮蓝 | #3E4A5C | 夜空、阴影 |

**小沙弥角色**：Q 版，头身比约 1:2。闭眼、本色光头（不要橙色）、灰布僧衣（白天）。**不要橙头配黄袈裟**，那是 Sansa 的造型。一个模型，所有人共用；靠名字区分，不提供换装。

**动画**：站、走、坐、合十、礼拜、敲木鱼、转念珠，共 7 个。

**界面**：字体 Noto Serif SC。底部动作栏无底框，用墨线分隔，选中项下加一道墨线。夜间动作栏改为深色半透明底配灯火色字。按钮触控区不小于 44 × 44 px。

**页脚固定文案**：「半山是一个中式静心空间，不是宗教机构，与任何寺院无关。」

### 4.3 房间与匹配

- 时区分桶：`tzBucket = 用户 UTC 偏移（四舍五入到整小时）`，例如意大利冬令时是 `+1`。每个桶对应一个 `Directory` DO。
- `GET /join?tz=+1` → Directory 返回 `roomId`：
  - 优先选当前 30–90 人的殿（不冷清也不拥挤）；
  - 没有就选人数最多但未满的殿；
  - 都满了（100 人）就新开一个殿。
- 客户端拿到 `roomId` 后连接 `wss://…/ws/:roomId`。
- Room 每次有人进出都向 Directory 报告当前人数。
- 断线 30 秒内带同一个匿名 ID 重连，保留原来的位置和蒲团。

### 4.4 匿名身份

- 首次访问时在 localStorage 生成 `anonId`（UUID v4）。
- 只用于重连、限制每天一盏灯、去重统计。不和任何个人信息关联。

### 4.5 同步协议（JSON over WebSocket，结构定义在 `packages/shared/src/protocol.ts`，前后端都用 zod 校验）

客户端 → 服务器：

| type | 字段 | 说明 |
|---|---|---|
| `hello` | anonId, name | 连接后第一条 |
| `move` | x, z | 目标点；服务器只校验在可走范围内 |
| `act` | action: `hezi` / `bai` / `muyu` / `nianzhu` | 身体动作 |
| `sit` | seat: 0–99 | 请求坐到某个蒲团 |
| `stand` | — | 起身 |
| `incense` | — | 上了一炷香（只用于香炉里多一炷的显示） |
| `lamp` | — | 点了一盏灯，**不带文字** |
| `rename` | name | 换名，每次连接限一次，名字必须来自 §8 的名字池 |

服务器 → 客户端：

| type | 说明 |
|---|---|
| `snapshot` | 进殿时下发全量状态：所有人（id、名字、位置、状态）、蒲团占用、香炉里的香数、灯数 |
| `delta` | 每秒 5 次，只发变化：进出、新目标点、动作、坐起 |
| `seat_ok` / `seat_taken` | 蒲团请求的结果，由服务器裁决 |
| `lamps` | 灯数变化 |
| `incense_count` | 香炉里正在燃的香数 |

规则：
- 客户端只发目标点，走路动画由每个客户端各自插值，带宽控制在每人每秒 1 KB 以下。
- 限流：每个连接每秒最多 10 条消息，超出直接丢弃；连续超限 10 秒就断开。
- 服务器不接收、不存储、不转发任何用户输入的文字（名字只能从名字池里选）。

### 4.6 存储（Durable Object 自带存储）

- Room：蒲团占用（内存即可）；香炉里的香（每炷带过期时间，5 分钟）；灯（每盏带过期时间，24 小时，只存 anonId 的哈希和过期时间，用于限制每天 1 盏）。
- Directory：各殿人数。

### 4.7 时间系统（全部在客户端计算，不经过服务器）

- `dayPhase(now)` → 晨 / 日 / 暮 / 夜。
- `nextBellDrum(now)` → 下一次钟鼓的时间和类型。
- `solarTerm(date)` → 节气名和对应的季节、天气组合。
- `incense`：本地计时 5 分钟，到点播磬声。
- 所有时间函数做成纯函数，必须有单元测试，包括跨午夜、夏令时切换、节气交界日。

### 4.8 性能预算（手机优先）

- 首屏下载 ≤ 5 MB（glb 经 Draco/Meshopt 压缩，贴图用 KTX2）；音频懒加载。
- 中档安卓机（参考 Pixel 6a / 红米 Note 12）稳定 30 fps；整场 draw call ≤ 100。
- 100 个角色用 GPU instancing（InstancedMesh 或 instanced skinned mesh 方案）；距离超过 15 米的角色降低动画帧率。
- 低端设备自动关闭阴影和粒子。
- 首帧可交互时间（4G 网络）≤ 8 秒。

## 5. 开发顺序与验收标准

按顺序做，每个里程碑完成并通过验收后再开始下一个。开发期用白模（几何体）和占位音频，不要等正式美术资源。

### M0 项目骨架
- 建好 pnpm workspace、TS 配置、ESLint/Prettier、vitest。
- `apps/web` 能本地跑起来；`workers/realtime` 能用 `wrangler dev` 跑起来。
- **验收**：`pnpm dev` 同时启动前端和 Worker；`pnpm test` 通过；`pnpm build` 无报错。

### M1 单人白模场景
- 山门、石阶、庭院、大殿用基础几何体搭出来；100 个蒲团、香炉、功德箱就位。
- 点击地面移动、拖动旋转、缩放、镜头限位。
- **验收**：手机浏览器（iOS Safari、安卓 Chrome）里能从山门走进大殿，镜头不穿墙、不翻转。

### M2 角色与动作
- 小沙弥用白模（球头加锥身）代替；做好动画状态机：站、走、坐、合十、礼拜、木鱼、念珠。
- 底部动作栏；礼拜只在坐着时可用。
- **验收**：七个状态切换不卡顿、不穿模；动作栏按钮触控区 ≥ 44 px。

### M3 多人同步
- Directory 和 Room 两个 DO；`/join` 匹配逻辑；WebSocket 协议（§4.5）。
- snapshot + delta，客户端插值；断线 30 秒重连保留位置。
- **验收**：
  - 两个浏览器能互相看到对方走动和做动作，延迟感受 < 300 ms；
  - 第 101 人进入时被分到新殿；
  - 断网 20 秒再恢复，回到原位；
  - 发送畸形消息或超频消息，服务器不崩溃。

### M4 物件交互
- 走近物件才出现按钮；蒲团坐下（服务器裁决占用）；香炉上香；功德箱面板。
- **验收**：两个人同时抢同一个蒲团，只有一个人坐上，另一个收到「这个蒲团有人了」；离开 2 米外按钮消失。

### M5 时间系统
- 昼夜四段光照与过渡；晨钟暮鼓与「钟声将至」提示；节气判断与四季天气；一炷香计时和磬声。
- **验收**：
  - 时间函数单元测试全部通过（跨午夜、夏令时、节气交界）；
  - 用调试面板手动改时间（仅开发环境），能看到四段光照和钟鼓提示；
  - 一炷香 5 分钟到点响磬，期间关掉再打开页面，计时不重置。

### M6 一盏灯、随喜、统计
- 一盏灯面板、本地存储文字、服务器只收信号；殿内灯光；每天 1 盏的限制。
- 随喜面板与外链（读环境变量，未配置就隐藏按钮）。
- 接入 Plausible，埋好 §6 的事件。
- **验收**：
  - 用浏览器开发者工具检查网络请求，确认灯的文字**从未发出**；
  - 同一个浏览器当天第二次点灯被拒绝，有温和的提示；
  - 统计后台能看到事件。

### M7 降级、性能、移动端打磨
- 2D 降级模式；设备分级自动降画质；资源压缩脚本。
- **验收**：
  - 禁用 WebGL 后进入 2D 模式，一炷香、一盏灯、钟鼓仍可用；
  - 满足 §4.8 全部性能预算（在中档安卓机实测，附截图或录屏）。

### M8 压测与上线
- k6 脚本模拟 1 万个并发连接，分布到约 100 个殿。
- 部署到 Cloudflare（Pages + Workers + R2），配置正式域名。
- **验收**：1 万并发下消息无丢失性错误、单殿广播延迟 < 500 ms；生产环境手机实测走通完整流程（进殿 → 走动 → 坐下 → 上香 → 点灯 → 听钟 → 下山）。

### 正式美术替换（与 M3–M7 并行，资源到位后替换）
- 替换场景、角色、动画、音频，不改代码结构。
- **验收**：替换后性能预算仍达标。

## 6. 统计事件（只记匿名事件，不记任何文字内容）

`enter`（进殿成功）、`load_fail`（未进入场景就离开，带地区）、`sit`、`act`（带动作类型）、`incense_start`、`incense_done`、`lamp`、`donate_open`、`donate_click`、`bell_present`（钟鼓时在殿内）、`fallback_2d`、`leave`（带停留时长）。

目标指标（上线后校准）：7 日回访率 ≥ 15%；单次停留中位数 ≥ 4 分钟；加载失败率 ≤ 10%。
